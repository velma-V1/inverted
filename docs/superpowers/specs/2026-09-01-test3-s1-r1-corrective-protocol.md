## 1. Why R1 exists

The first real S1 execution, `test3-s1-20260901-111233`, completed 6 matched arm-tasks per arm with 24 physical model calls and returned `S1_SCREEN_NON_DECISIVE`.

That run is retained as evidence but is invalid for a primary S1 causal claim because the runtime generated a fresh initial executor output inside every arm and invoked `retry` / `targeted_repair` only after failure. When the initial executor succeeded, the ordered intervention disappeared. The matched-prefix reservation also reduced Holdout A to 6 tasks because the runtime reserved a three-call worst case that included the initial executor.

Classification:

`INVALID_FOR_PRIMARY_S1_CAUSAL_CLAIM — INTERVENTION_EXPOSURE_COLLAPSE`

The defect is in the measurement/runtime protocol, not in the model evidence.

## 2. Causal question retained

> Does fixed component order have enough causal value to justify further fixed-topology optimization?

R1 does not change the four S0-frozen arms, the selected models, or the 80-call campaign ceiling. It changes only the experimental exposure protocol so the intervention actually occurs.

## 3. Fresh holdout

R1 uses `Holdout A-R1`, not the already-exposed Holdout A.

- exactly 10 deterministic cases
- disjoint seeds from Test-2, original S1 Holdout A, and later Test-3 holdouts
- mixed `state`, `policy`, and `reconciliation` families
- mixed complexity levels 1–4
- each case begins from the same deterministic, verified-bad candidate for all four arms
- the seeded fault is generated by benchmark code and is never exposed to model prompts as hidden-gold metadata

The initial failed candidate consumes zero model calls. It is an intervention fixture, not a claimed model output.

## 4. Exact compute contract

R1 uses exactly:

- 10 matched cases
- 4 arms
- 2 physical model calls reserved per arm-case
- 20 physical calls per arm
- 80 physical model calls total

No cache hits and no adapter transport retries are permitted.

A run with anything other than exactly 80 physical model calls is invalid for the primary S1 claim.

## 5. Arm semantics

### S1-A0 — best-single baseline

Starts from the same deterministic failed candidate as every other arm.

It receives two best-single executor opportunities. If the first active regeneration succeeds, the second reserved call is executed as a compute-control shadow call and cannot change the selected candidate. If the first fails, the second executor call is active.

### S1-A1 / S1-A2 / S1-A3 — fixed-order arms

Each arm traverses its S0-frozen production order.

- `requirement_validator`: deterministic, zero calls
- `retry`: best-single executor regeneration
- `targeted_repair`: frozen Test-2 repairer model using structured deterministic failure evidence
- `final_validator`: deterministic and terminal on failure

A model-call component is active only while the architecture remains live and the current candidate has not already succeeded. Once success or a terminal validator is reached, any still-reserved model-call component is executed only as a shadow compute control. Shadow responses are recorded but are forbidden from changing the candidate, trace state, or final outcome.

This preserves architecture semantics while equalizing physical compute.

## 6. Intervention-exposure gate

Before any primary S1 verdict is authorized, the evidence must prove all of the following:

1. `protocol_revision == "S1-R1"`
2. `holdout == "A-R1"`
3. exactly 10 matched cases are completed by all four arms
4. exactly 20 physical calls are used by each arm
5. exactly 80 physical calls are used globally
6. every seeded initial candidate is deterministically verified unsuccessful before inference
7. every arm-case has at least one active model intervention
8. the fixed-order arms expose the first call-bearing component implied by their frozen order
9. at least two distinct first active call-bearing operations exist across the fixed/order arms, so the order intervention is not degenerate
10. zero cache hits
11. zero internal/transport retries
12. hidden gold and target state never enter model prompts

If any item fails, the verdict is:

`S1_INVALID_INTERVENTION_EXPOSURE`

and `tier_a_architecture_claim` must be false.

## 7. Analysis

Primary analysis remains matched task-level comparison across all four arms.

Report:

- successes and catastrophes
- wins created / destroyed / net wins
- pairwise effects versus baseline and random-order control
- active versus shadow inference calls
- calls/tokens/latency
- first active operation by arm-case
- intervention exposure coverage

The original large-signal rule remains:

A production fixed order is a strong S1 signal only if it:

- gains at least 2 matched net wins versus baseline
- adds 0 catastrophes versus baseline
- gains at least 1 matched net win versus random control

The S0 260-cluster estimate remains authoritative for the configured small target effect. Therefore a null 10-case R1 screen cannot rule out a small fixed-order effect.
