# Harvest D Acceptance Criteria

Harvest D implementation is ready for real-model execution only when model-free CI proves:

- evidence/claim schemas and contamination gates;
- globally unique physical model-call identity;
- deterministic state/version/authority/transaction safety;
- no authorization resurrection or duplicate irreversible effects;
- exact-state intervention/sham matching;
- independent system-involvement telemetry;
- versioned capability envelope;
- promotion/generalization/regression/rollback state machine;
- Qwen routing metrics and matched controls;
- deterministic artifact hashing/finalization;
- offline dry run with no cloud/local-model inference.

Real-model results are not part of implementation readiness.
